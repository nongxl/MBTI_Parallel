# 总体产品定义

暂定产品可以先用一个工作名：

> **MBTI Parallel / Parallel Self**
>
> 一个离线运行在 Cardputer 上的 MBTI 决策分支玩具。

核心体验：

> **提出/构造一个轻量决策情境 → 16 种 MBTI 分别做选择 → 找出最大的意见分歧 → 用户探索不同人格为什么这么选。**

核心原则：

* **离线优先**
* 第一版**不依赖 LLM**
* 第一版**不需要额外硬件**
* 不做聊天机器人
* 不做生产力工具
* 不做严肃心理测试
* 不试图预测未来
* 不需要用户输入长文本
* 单次体验控制在 **30 秒～2 分钟**
* MBTI 是唯一人格体系
* “好玩”和“想再玩一次”比“准确”重要

---

# Phase 1：先做“人格分支引擎”

### 目标

**完全不考虑 UI，也不考虑 Cardputer 输入。**

先把最核心的东西跑起来：

> 同一个决策情境 → 16 个 MBTI → 产生不同选择。

---

### 1. 定义 MBTI 人格模型

不要试图做专业心理学模型。

给 16 型建立几个简单的行为倾向：

* Risk：风险接受程度
* Novelty：新奇偏好
* Logic：逻辑/情感倾向
* Social：社交因素权重
* Planning：计划/即兴倾向
* Efficiency：效率/体验倾向

这些参数只是**游戏化人格模型**。

---

### 2. 定义决策原型

第一版只需要：

```text
GET
GO
DO
SAY
CHOOSE
KEEP
QUIT
CHANGE
ACCEPT
REFUSE
WAIT
RISK
```

不要继续增加。

---

### 3. 定义决策因素

例如：

```text
RISK
COST
TIME
NOVELTY
SOCIAL
EFFORT
UNCERTAINTY
EMOTIONAL VALUE
PRACTICAL VALUE
```

然后建立：

```text
Scenario
    ↓
Decision Factors
    ↓
MBTI
    ↓
YES / NO / MAYBE
```

---

### 4. 第一阶段的验收标准

Coding AI 最终应该能运行类似：

```text
Scenario:
GET
Cost: HIGH
Need: LOW
Novelty: HIGH
Risk: MEDIUM

INTJ  → MAYBE
ENTJ  → YES
ISTJ  → NO
ENFP  → YES
...
```

并且：

> **16 型不能全部得出一样的答案。**

这是第一阶段最重要的测试。

---

# Phase 2：建立“情境构造器”

这一阶段解决我们刚才讨论的最大问题：

> **没有 LLM，用户怎么表达自己的问题？**

答案就是：

> **通过有限选项组合一个抽象决策情境。**

---

## 首页

```text
WHAT'S ON
YOUR MIND?

GET
GO
DO
SAY
CHOOSE
CHANGE
```

选择之后进入下一层。

例如：

```text
GET

WHY?

WANT
NEED
CURIOUS
GIFT
```

然后：

```text
WHAT'S STOPPING YOU?

PRICE
RISK
TIME
UNCERTAIN
NONE
```

再：

```text
HOW MUCH?

LOW
MEDIUM
HIGH
```

---

### 注意

**这里不要追求“还原用户真实问题”。**

用户并不是在创建一个严谨的 Scenario。

他只是在告诉机器：

> “大概是这么回事。”

这正是这个玩具轻量化的关键。

---

### Phase 2 验收

用户从开机到生成 Scenario：

> **最多 5～7 次按键操作。**

最好：

> **20 秒以内。**

---

# Phase 3：设计真正的核心体验——“16 人格分支”

这是整个项目最重要的一阶段。

前两个阶段是功能。

**第三阶段才是产品。**

---

## 开始模拟

```text
SIMULATING...

ISTJ
INTJ
ENTP
ENFP
...
```

可以使用非常简单的动画：

```text
●
● ●
● ● ●
● ● ● ●
```

或者：

```text
01
04
08
16
```

营造“分支展开”的感觉。

---

## 最终结果

不要直接把 16 个结果全部铺出来。

首先显示：

```text
11 YES
4 NO
1 MAYBE
```

然后：

> **BIGGEST SPLIT**

```text
ENTP
YES

        VS

ISTJ
NO
```

这就是用户最想点进去的东西。

---

## Explore

用户按左右键：

```text
← ENTP

YES

"Opportunity
is worth the risk."

→ ISTJ

NO

"There's no need
to take the risk."
```

---

### Phase 3 验收标准

用户应该产生：

> **“卧槽，为什么这两个完全相反？”**

如果没有这种感觉，就不要急着进入下一阶段。

---

# Phase 4：加入“我的人格”

这一步开始形成长期使用价值。

第一次启动：

```text
WHAT'S YOUR
MBTI?

16 TYPES
[UNKNOWN]
```

用户可以：

```text
INTJ
```

或者：

```text
I DON'T KNOW
```

不要强迫测试。

---

## 结果界面

例如用户是 ENTP：

```text
YOUR TYPE

ENTP

THIS TIME:

ENTP     YES
ISTJ     NO
INTJ     YES
...
```

甚至可以显示：

```text
YOU AGREED WITH

ENTP
INTJ
ESTP
```

---

## 再进一步：记录用户自己的选择

例如每次模拟结束：

```text
WHAT WOULD
YOU DO?

YES
NO
MAYBE
```

这个动作应该是**可选的**。

记录：

```text
Your choice
vs
16 MBTI
```

累计以后：

```text
YOUR DECISIONS

ENTP  ███████
INTJ  █████
ESTP  ████
ISTJ  ██
```

不要做复杂统计。

只做一个：

> **“你的选择最近最像谁？”**

---

# Phase 5：内容与“把玩性”

到了这里才开始做大量情境。

### Scenario Pack

例如：

**日常**

* 要不要买一个想买很久的东西？
* 要不要接受一个临时邀请？
* 要不要尝试一家陌生餐厅？
* 要不要改变原来的计划？

**社交**

* 要不要主动联系一个很久没联系的人？
* 要不要告诉朋友一个真实想法？
* 要不要参加一个不熟悉的聚会？

**冒险**

* 要不要临时去一个陌生地方？
* 要不要尝试一个新爱好？
* 要不要接受一个未知机会？

**趣味题**

* 捡到 100 元怎么办？
* 发现老板不在，要不要提前下班？
* 朋友说“我有个秘密”，你会不会继续问？
* 旅行只剩一天，你会怎么安排？

这些场景不需要非常严肃。

**甚至越轻越好。**

---

# Phase 5 还应该加入一个非常重要的模式

## RANDOM

这是我认为 EDC 属性非常重要的功能。

用户无聊了：

```text
RANDOM
```

机器随机生成一个情境：

```text
YOU HAVE
ONE FREE DAY.

WHAT DO YOU DO?
```

然后：

> 16 personalities simulate。

这时候用户甚至不需要自己有问题。

**它本身就能制造一个“拿出来玩一下”的理由。**

# 最终产品结构

做完这五阶段，整体大概就是：

```text
┌─────────────────────┐
│                     │
│      PARALLEL       │
│                     │
│   WHAT'S THE        │
│   QUESTION?         │
│                     │
│ > DECIDE            │
│   RANDOM            │
│   MY TYPE           │
│   HISTORY           │
│                     │
└─────────────────────┘
```

### DECIDE

自己构造一个情境。

### RANDOM

随机生成一个轻松情境。

### MY TYPE

查看自己与 MBTI 的关系。

### HISTORY

非常轻量的历史统计。

# LLM 放在哪里？

我建议**暂时完全不做**。

等 Phase 1～5 完成以后，再把 LLM 当成：

> **Phase 6：Natural Input**

而不是产品核心。

届时增加：

```text
TYPE A QUESTION

> should I buy this camera?
```

LLM 只负责把自然语言转换成：

```text
GET
WANT
COST
NOVELTY
RISK
```

然后继续走你已经做好的：

```text
Scenario
 ↓
MBTI Engine
 ↓
16 Branches
 ↓
Explore
```

这样即使 API 没了：

> **产品仍然完整。**

这是非常重要的架构决策。

---

# 我建议 Coding AI 的开发顺序

可以直接按这个顺序喂：

| 阶段     | 核心目标            | 是否需要网络 |
| ------ | --------------- | ------ |
| **01** | MBTI 决策引擎       | ❌      |
| **02** | 情境构造器           | ❌      |
| **03** | 16 人格分支 UI      | ❌      |
| **04** | 用户人格 + 轻量记录     | ❌      |
| **05** | 随机情境 + 内容库 + 打磨 | ❌      |
| **06** | LLM 自然语言输入      | ✅ 可选   |

其中 **01～03 是 MVP 的真正核心**。

如果做到 Phase 3，你拿着 Cardputer 给别人：

> “你随便选一个问题，我们看看 16 种人格怎么选。”

对方玩完以后还会主动问：

> **“那 ENFP 呢？”**
>
> **“为什么 ISTJ 是这个答案？”**
>
> **“那我的 MBTI 呢？”**

那就说明这个产品成立了。

反过来，如果 Phase 3 玩起来没意思，后面加历史、LLM、更多场景都只是堆功能。

**所以我会强烈建议：第一轮 Vibe Coding 甚至先不要做持久化、不要做网络、不要做语音。先把“一个问题 → 16 种人格分裂 → 找到最大分歧 → 点进去看为什么”这个 30 秒体验打磨出来。**
